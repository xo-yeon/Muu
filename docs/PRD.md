# PRD: Muu

## 1. 제품 개요

Muu는 사용자의 감정과 행동 패턴을 바탕으로 오늘의 인간 유형과 상태 리포트를 생성하는 모바일 퍼스트 감정 체크 앱이다.

화면은 귀여운 도트/픽셀 감성의 2D 게임 UI처럼 보이지만, 결과 문구는 현실적이고 약간 팩트폭력 느낌을 유지한다.

## 2. 목표

기존 감정 기록 앱은 기록 자체가 무겁거나 지속성이 떨어지는 문제가 있다. Muu는 사용자가 짧은 질문 플로우를 통해 자기 상태를 가볍게 확인하고, 바로 이해 가능한 결과를 받는 경험을 목표로 한다.

MVP 목표:

- 12개 질문으로 현재 상태를 빠르게 체크한다.
- 감정 태그와 자유 입력을 통해 사용자의 맥락을 보강한다.
- 같은 답변이면 항상 같은 결과가 나오도록 룰 기반 분석을 제공한다.
- 귀여운 UI와 현실적인 결과 문구의 대비를 만든다.
- 최근 결과를 localStorage에 저장한다.

## 3. 대상 사용자

- 감정 기록, 자기 관찰, 심리 유형 콘텐츠를 좋아하는 사용자
- 무거운 일기보다 가벼운 상태 체크를 원하는 사용자
- MBTI/테스트형 콘텐츠를 좋아하지만 조금 더 일상적인 피드백을 원하는 사용자
- 귀여운 픽셀 UI와 직설적인 문구의 대비를 즐기는 사용자

## 4. v1 MVP 범위

포함:

- Home 화면
- `/check-in` 상태 체크 플로우
- 12개 질문 플로우
- 질문 한 번에 하나씩 표시
- 진행률 표시
- 감정 태그 다중 선택
- 선택형 자유 입력
- 룰 기반 인간 유형 분석
- OpenAI API 기반 보조 관찰

  - 메인 홈과 결과 페이지에서 이동 가능
  - `decision.*`, `lab.*` 서브도메인에서는 결정 실험실 컨텐츠를 표시

## 5. 사용자 플로우

```txt
Home
  -> 시작하기: /check-in 이동
12개 질문
  -> 감정 태그 선택
자유 입력
  -> 룰 기반 분석
  -> localStorage 저장
Result
  -> 다시 하기 또는 최근 결과 복원
  -> 결정 실험실
```

## 6. 화면 요구사항

### Home

목적: 서비스 진입 화면.

포함 요소:

- Muu 로고
- 픽셀 캐릭터
- 시작 버튼
- 짧은 소개 문구
- 최근 결과 카드

동작:

- 시작 버튼은 `/check-in`으로 이동한다.
- 최근 결과 카드는 `/check-in?restore=last`로 이동해 저장된 결과를 바로 복원한다.

현재 문구 방향:

```txt
오늘의 인간 상태를 분석합니다
귀여운 도트 너머, 현실적인 오늘의 기록을 담습니다.
```

### 질문 플로우

요구사항:

- 총 12개 질문
- 각 질문은 5개 선택지
- 한 번에 하나의 질문만 표시
- 선택 즉시 다음 질문으로 이동
- 상단 진행률과 `n/12` 카운터 표시
- 이전 버튼 제공

질문 데이터는 `src/data/questions.ts`에서 관리한다.

### 감정 태그 선택

요구사항:

- 질문 완료 후 표시
- 다중 선택 가능
- 최소 1개 선택 필요
- 선택된 태그는 분석 점수에 반영

현재 태그:

- 불안
- 무기력
- 지침
- 외로움
- 초조함
- 죄책감
- 막힘
- 회피 욕구
- 안정감
- 후련함
- 귀찮음
- 괜찮음
- 멍함
- 답답함
- 무난함

### 자유 입력

요구사항:

- 선택 입력
- 비워도 결과 생성 가능
- 최대 300자
- 입력이 있을 때만 OpenAI 보조 관찰 문구 표시
- 입력 내용은 인간 유형 자체를 뒤집지 않고 보조 신호로만 사용

### 결과 페이지

필수 표시 요소:

- 인간 유형
- 오늘의 인간 유지 행동
- 팩트 한 줄
- 상태 요약
- 획득 아이템(마지막 배치)
- 픽셀 캐릭터
- 자유 입력이 있을 경우 AI 관찰
- 결정 실험실 이동 버튼

문구 톤:

- 과장된 위로나 치료적 진단 금지
- 사용자를 비난하지 않음
- 귀엽지만 직설적
- "괜찮아"만 반복하지 않고 행동 단위를 제안

## 7. 인간 유형

현재 MVP의 결과 유형:

1. 과열된 계획 중독형
2. 조용한 번아웃 진행형
3. 미래 걱정 시뮬레이션형
4. 인간 기능 저전력형
5. SNS 회피 생존형
6. 생각보다 잘 살아있는 인간형
7. 감정 습도 과다형
8. 생활 시스템 과부하형

## 8. 분석 로직

분석 축:

```ts
type Axis =
  | 'overthinking'
  | 'avoidance'
  | 'burnout'
  | 'anxiety'
  | 'execution'
  | 'socialFatigue'
  | 'emotionalSensitivity'
  | 'stability'
  | 'dopamineSeeking';
```

방식:

- 각 질문 선택지는 여러 분석 축에 점수를 더하거나 뺀다.
- 감정 태그도 분석 축 점수에 반영한다.
- 자유 입력은 키워드 기반 보조 점수만 추가한다.
- 최종 점수와 고정 우선순위로 결과 유형을 결정한다.
- 같은 입력이면 항상 같은 결과를 반환한다.

AI 정책:

- 실제 OpenAI API는 서버 route handler에서만 호출한다.
- `OPENAI_API_KEY`는 서버 환경 변수로만 사용한다.
- OpenAI는 자유 입력에 대한 보조 관찰 문구만 생성한다.
- AI는 인간 유형을 변경하지 않는다.

## 8-1. Decision Lab / 결정 실험실

목적: 사용자가 고민 중인 선택지 2~4개를 입력하면, 현재 인간 유형과 감정 상태를 반영해 “지금 상태의 나에게 더 나은 선택”을 추천한다.

진입:

- 홈 화면의 `결정 실험실` 버튼
- 결과 페이지의 `이 상태로 결정 실험실` 버튼
- `/decision-lab` 페이지
- `decision.*`, `lab.*` 서브도메인

입력:

- 고민 주제: 필수
- 선택지: 2~4개
- 비교 기준: 기본 기준 고정
  - 실행 난이도
  - 후회 가능성
  - 지금 상태와의 적합도
  - 회복 도움
  - 장기적 도움

추천 방식:

- 룰 기반 점수 계산이 기본이며 AI 없이도 동작해야 한다.
- 선택지 텍스트, 현재 인간 유형, 감정 태그, 감정 날씨, 자유 입력 신호를 반영한다.
- AI는 추천 선택지나 점수를 바꾸지 않고 보조 코멘트만 생성할 수 있다.
- 같은 DecisionSession 입력은 항상 같은 DecisionResult를 반환해야 한다.

결과 표시:

- 추천 선택지
- 선택지별 점수 비교
- 현재 상태 기반 추천 이유
- 팩트 한 줄
- 지금은 하지 않는 게 좋은 선택
- 선택 완료 버튼
- 다시 비교하기 버튼

## 10. 저장 정책

최근 결과는 localStorage에 저장한다.

```txt
key: muu:v1:last-result
```

저장 항목:

- 저장 시간
- 질문 답변
- 감정 태그
- 자유 입력
- 분석 결과

Home 화면에서 최근 결과가 있으면 카드로 표시하고, 클릭 시 `/check-in?restore=last`에서 결과 페이지로 복원한다.

Decision Lab은 최근 결정 context와 최근 결정 결과를 localStorage에 저장한다.

```txt
key: muu:v1:decision-context
key: muu:v1:last-decision-session
```

저장 항목:

- 현재 인간 유형 결과
- 감정 태그
- 자유 입력
- 고민 주제
- 선택지
- 룰 기반 추천 결과
